PB310

AUR report card · Rule reference

anonymized-fetch

Nothing a package legitimately needs is fetched over Tor or through a SOCKS proxy: upstreams publish on the open web, and a checksummed source= entry is verified however it arrived. Routing a fetch through torsocks or proxychains, curl's --socks5/-x socks…, an ALL_PROXY=socks… environment, or to a .onion host hides where the payload comes from and lets its server tell a victim's request from a reviewer's. This is the xsnow/xsnow-bin incident of August 2026, whose build() pulled a second stage through torsocks; generic network access is PB201 and PB501.

Example
Suppress

If a package trips this rule on purpose and you have reviewed it, put this directive on the offending line or the line above it:

# pkglint: ignore=PB310

It covers only that line pair, in that file. Passing --ignore PB310 turns the rule off for a whole run instead.
